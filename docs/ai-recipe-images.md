# Фото выбранного ИИ-рецепта

## Пользовательский сценарий

1. Пользователь получает ровно три текстовых варианта рецепта без изображений.
2. После нажатия «Выбрать этот вариант» открывается экран выбранного рецепта.
3. Только для этого рецепта вызывается Edge Function `recipe-image`.
4. Фото показывается перед кнопкой «Добавить в план питания».
5. Если генерация недоступна, рецепт всё равно можно добавить без фото.

## Стоимость и кеширование

По умолчанию используется `gpt-image-1-mini`, качество `low`, квадратный WebP 1024×1024. Стабильный SHA-256 от названия, описания и ингредиентов образует путь `ai-recipes/<hash>.webp` в приватном bucket `content-images`. Повторный выбор того же рецепта возвращает кешированное изображение без нового запроса к OpenAI.

Опциональные Edge Function secrets:

- `OPENAI_IMAGE_MODEL` — модель, по умолчанию `gpt-image-1-mini`;
- `RECIPE_IMAGE_BUCKET` — bucket, по умолчанию `content-images`.

Обязательные secrets уже используются другими функциями:

- `OPENAI_API_KEY`;
- `ALLOWED_ORIGINS`.

## Развёртывание staging

Запустить вручную workflow **Deploy staging Edge Functions** и ввести `DEPLOY-STAGING-FUNCTIONS`. Workflow разворачивает `recipe-image` вместе с остальными функциями. Во время проверки не запускать реальную генерацию изображений без необходимости.
