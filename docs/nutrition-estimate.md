# Автоматический расчёт КБЖУ

Ручной ввод продуктов сохраняет продукты по отдельности, как ввёл пользователь. КБЖУ рассчитывается серверной Edge Function `nutrition-estimate` после нажатия «Рассчитать КБЖУ», показывается до сохранения и остаётся редактируемым.

## Безопасность

- `OPENAI_API_KEY` хранится только в Supabase Edge Function Secrets.
- Ключ не добавляется во frontend и не имеет префикса `VITE_`.
- Функция принимает запросы только от авторизованных пользователей и разрешённых origin.
- За один запрос принимается от 1 до 20 продуктов с ограниченной длиной полей и количества.
- Ответ OpenAI проверяется структурированной JSON-схемой.
- Запросы OpenAI выполняются с `store: false`.

## Настройка staging

В Supabase откройте **Edge Functions → Secrets** и добавьте:

```text
OPENAI_API_KEY=<ключ OpenAI API>
```

`ALLOWED_ORIGINS` должен уже содержать адрес Telegram Mini App.

После merge вручную запустите GitHub Actions workflow **Deploy staging Edge Functions** и введите подтверждение:

```text
DEPLOY-STAGING-FUNCTIONS
```

Фактический расчёт требует активного биллинга OpenAI API. Значения КБЖУ являются ориентировочными: конкретная марка и способ приготовления могут изменить результат, поэтому пользователь может исправить цифры перед сохранением.
